# SP-01：本地查询、贡献和下钻契约

状态：研究实验；数据全部合成；没有调用模型、没有图表 UI、没有访问业务数据。

## 运行

在本目录执行 `uv run --frozen --python 3.12 run.py`。`uv.lock` 锁定实验依赖；首次运行需要下载 Python 环境/依赖（若本机尚无）。

## 验证问题

DuckDB 能否承接模型之外的确定性计算，并通过有限的 QuerySpec 保留指标、快照、对比期、筛选与下钻关系？

输入只有两份 8 行合成 CSV。正常场景：销售额 3000 → 2600，总变化 -400；东区 -700，西区 +300，说明“负向变化”和“正向抵消”必须同时显示。东区对净下降贡献 175%，西区 -75%，不可强制裁到 0–100%。平衡场景总量不变，但东西两区各有 700 的反向变化。

验证包含固定总额、贡献核对、带父级筛选下钻、返回原查询、比率按分子分母重算、拒绝比率使用加法贡献、零净变化、字段白名单、值参数绑定、错误快照拒绝。

## 边界

- 固定字段白名单与参数绑定只覆盖这个受限编译器；不是任意 SQL/Python 的安全沙箱。
- 内存设置不等于操作系统级内存限额；没有做大文件压力测试。
- `chart_contract_not_rendered` 仅展示共享结果契约，不证明 ECharts 或真实交互已经运行。
- 贡献是描述性拆解，不证明因果。这里没有自动寻找维度、模型理解、真实经营诊断或统计显著性验证。
- 快照哈希只覆盖合成输入；产品实现还需要解析配置、schema、指标版本和转换版本共同参与标识。

官方接口参考：[Python API](https://duckdb.org/docs/current/clients/python/reference/)、[文件读取](https://www.duckdb.org/docs/current/clients/python/data_ingestion)。本机结果见 `results.json`。
