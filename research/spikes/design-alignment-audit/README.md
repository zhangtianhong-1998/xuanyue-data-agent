# 代码与设计审查的合成复核

日期：2026-10-03。对应[审查报告](../../../docs/research/12-code-design-review-20261003.md)。这是缺陷观察实验，不是产品功能实现，也不将观察到的错误行为固定为回归测试的正确答案。

从仓库根目录使用已安装产品依赖的环境运行：

```bash
.venv/bin/python research/spikes/design-alignment-audit/probe.py
```

脚本只使用合成文字、脚本模型、临时模型目录和临时 SQLite；不读取仓库的 `xuanyue.toml`、`.env` 或运行库，不创建真实供应商客户端，不发起网络请求。临时文件在运行后清理。依赖与代码版本在[观察记录](observations.json)中保存；不是完整环境锁文件。

四组观察分别复核：

- `long_history`：八轮历史实际有多少进入模型请求，最终状态和公开事件是否反映截断。
- `tool_exception`：合成异常标记是否进入产品保存的公开事件及下一次模型请求。
- `iteration_limit`：达到现有限制时，真实请求数、工具执行数、公开开始事件及终态是否一致。
- `mutable_model_binding`：模型被会话引用后是否仍能修改目的地，以及旧 Run 是否保留目的地版本。

2026-10-03 的结果：AgentScope 长历史的八个标记全部消失，Run 仍完成；合成工具异常正文进入其公开记录与模型请求。LangGraph 在循环上限下实际调用模型四次，记录五次开始。引用中的产品模型 ID 可以保留原名而更换目的地与上游名。具体影响、现阶段限制和修复建议只在审查报告维护。

2026-10-07 的 A2 前后复核使用相同 `probe.py`，原始观察记录保持不变。[本次对照](a2-recheck-20261007.json)记录基线提交、修复后源文件哈希和精简结果；其中 A3 的失败仍保留。运行 `.venv/bin/python -m unittest discover -s tests -p test_tool_errors.py -v` 可重复工具失败的双内核验收。现行行为与未验证范围只在[修复计划 A2](../../../docs/engineering/05-code-review-remediation.md#a2-的实际结果2026-10-07)维护。

保留边界：工具异常场景使用额外登记的合成只读工具，默认乘法工具没有被发现泄露真实秘密；历史场景仅验证内容是否送达，不评价模型理解；模型目录实验只改临时配置，没有向虚构域名发送内容。完整框架内部状态、真实网络费用和平台交互未验证。脚本异常时应保留失败，不能把输出改写成通过。
