# 执行沙盒候选设计

[返回设计导航](../00-discovery-summary.md) · 相关：[工作流与轨迹](04-workflow-and-trace.md)

日期：2026-09-25。状态：`proposed`，未经方案评审，不作为已批准实现。本文件是执行沙盒的唯一详细定义；供应商比较与原始依据见 [沙盒证据](../research/08-sandbox-profile-evidence.md)。

**目标用法：**模型提出运行一段 Python 代码统计文件。产品先检查用户授权和资源限制，再把获准的输入交给隔离环境；如果没有合格后端，就停在这一步并说明原因。当前只探测了本机可用性，还没有完成真实隔离测试。

按问题查阅：第 1–2 节说明哪些任务需要沙盒；第 3–4 节说明权限检查、执行接口与限制；第 5–6 节说明审批、撤销和运行记录；第 7 节列出待做的验证。

## 1. 本轮建议

把沙盒作为 Agent 内核必备接口，在首次允许模型生成代码执行之前完成一个真实后端。首轮候选为**本地 OCI 容器后端 + 产品自有权限代理**；Docker 与 Podman 的最终默认选择留待安装和隔离实验。AgentScope Runtime、OpenSandbox 是可替换的接入选项，不决定 Agent 编排框架。

没有合格后端时，界面继续支持对话、计划编辑和已经审查的确定性工具，生成代码节点返回 `sandbox_unavailable`。不能自动改用本机普通子进程，也不能自动上传到云沙盒。固定工具调用仍需校验输入、文件权限和资源预算。

这项建议的代价是容器/虚拟机的安装、启动和资源占用。若个人版本不接受这项依赖，下一阶段验证嵌入式 VM 或三平台原生隔离，再调整默认方案；当前不承诺零依赖安装。

## 2. 哪些内容进入沙盒

| 执行对象 | 默认处理 |
| --- | --- |
| 模型生成的 Python、shell、自定义脚本 | 必须进入通过策略检查的执行后端 |
| Skill 自带可执行脚本 | 与生成代码执行相同；Skill 的说明不能扩大权限 |
| 未受信任的本地 MCP server | 单独的受限进程/沙盒；不能因为使用 stdio 就认为已隔离 |
| 远程 MCP | 由连接器代理控制出网、凭据和参数；本地沙盒无法隔离远端服务器 |
| 项目自带确定性工具 | 可在受限 worker 中运行；禁止在 renderer 中执行。解析不可信文档仍需限制资源和依赖版本 |
| HTML/富文本/图表预览 | 使用独立渲染策略；其配置不代替代码执行隔离 |

模型、文件内容、网页、MCP 返回值和 Skill 正文均不能直接设置容器参数。它们可以提出所需能力，由产品校验后生成执行请求。

## 3. 边界与责任

调用顺序：**工作流节点 → 权限与预算检查 → SandboxProvider → 受限执行环境 → 产物校验与导入 → 节点事件**。

- 桌面 renderer 只通过已登记 IPC 提交请求；生成代码、模型 token 和容器管理连接不暴露给 renderer。
- 权限代理是受信任代码，独立于模型决策。它核对项目、动作、输入版本、授权和预算，再构造后端参数。
- 沙盒只能看到这次运行分配的输入、工作目录、临时目录；输出经代理检查后成为项目产物。
- 云模型、TTS、远程 MCP 和云沙盒分别有数据出口。允许某个模型接收摘要，不表示允许另一个服务获取原文件。

此设计针对生成代码或扩展误读文件、越权写入、未经授权出网、拖垮资源、遗留进程等问题。不声称防御宿主机已被入侵、所有内核/虚拟机漏洞或模型分析错误。上游安全更新仍需持续跟进。

## 4. SandboxProvider 的最小契约

以下名称为拟议接口，不是新增的已实现 SDK。复用统一 Run、Node、Artifact、Grant 标识，避免各后端另设一套业务对象。

| 方法 | 请求要点 | 返回/保证 |
| --- | --- | --- |
| `probe_capabilities()` | 后端配置和运行版本 | 运行位置、本地/远程、支持的文件/网络/资源限制、检查时间；未知项不能视为支持 |
| `prepare()` | run/node/attempt、输入引用、代码哈希、镜像 digest、策略版本、预算 | 不可变的执行清单与沙盒引用；缺少必需能力则拒绝 |
| `execute()` | 已校验的清单、短期授权引用 | 结构化状态、输出流、资源用量、错误；不能接受任意容器启动参数 |
| `cancel()` | 沙盒引用、取消原因 | 区分已接收请求、进程已停止、环境已清理 |
| `collect_artifacts()` | 已登记输出目录、大小/类型限制 | 校验后的产物引用；不导入路径越界、符号链接逃逸或任意宿主路径 |
| `destroy()` | 沙盒引用、保留策略 | 清理结果或可重试错误；失败进入待清理状态，不伪报已销毁 |

`ExecutionManifest` 记录：输入 Artifact 的版本/哈希、代码哈希、运行时和镜像版本、有效权限及策略版本、资源上限、网络模式、输出约束、授权引用、运行地点。真实凭据不写入清单或日志。传入模型的摘要不能替代实际执行清单。

### 4.1 默认限制

| 类别 | 候选规则 | 需检查的绕过方式 |
| --- | --- | --- |
| 文件 | 只读挂载本次输入；可写目录按 attempt 分配；根文件系统只读；不挂载用户主目录、凭据目录或容器 socket | `..`、符号链接、硬链接、挂载路径解析、输出文件替换；文件导入时再验证 |
| 网络 | 生成代码默认无网络；模型服务和数据下载通过受控代理完成 | 直接 IP、DNS、IPv6、重定向、环回/局域网/宿主服务；域名白名单不能只在提示词中实现 |
| 进程与权限 | 非 root 用户、移除非必要 capabilities、禁止提权；不共享宿主 PID/IPC，不允许 privileged | 子进程脱离、设备访问、宿主 socket、继承句柄；具体参数由后端适配器锁定 |
| 资源 | 明确 CPU、内存、进程数、墙钟时长、临时空间和输出量上限 | 子进程累计用量、输出洪泛、磁盘填满；不支持所需限制时拒绝该执行档位 |
| 凭据 | 密钥保留在代理；必需的网络动作使用限定目标的短期权限 | 环境变量、命令行、日志、异常和产物泄漏；不得直接继承宿主环境 |
| 依赖 | 使用锁定且预构建的镜像/依赖；首次拉取来源和版本可见 | 默认运行时 `pip install` / `curl` 会引入网络和供应链变化，需重新规划执行 |

网络白名单和磁盘配额不能仅靠字段声明。后端必须给出可执行的限制机制，并通过对应负测。首轮可用“完全无网络 + 有界临时文件系统”缩小验证范围。

### 4.2 本地后端的具体候选

- Docker/Podman 适配器只暴露固定配置档位，模型不能直接操作 daemon。Linux 原生容器与 Mac/Windows VM 内容器分别记录环境，不能把一端通过写成三端通过。
- 需要更强隔离或后台规模化管理时，再评估独立 VM、AgentScope Runtime、OpenSandbox。参考实现只用于减少适配工作，不替代本文件验收。
- 普通 `subprocess`、Python virtualenv、工作目录切换、命令字符串过滤都不作为代码隔离后端。

## 5. 审批、重放和撤销

用户审批页面显示具体动作、数据范围、运行地点、网络目的地、输出目录和资源预算。已有授权覆盖这些内容时直接执行，不反复询问；扩大范围时才产生新的待审批项。

授权与**执行内容及范围**绑定，而非仅与一句“允许运行”绑定。代码、输入、目标服务、写入范围、镜像或策略发生变化后，重新校验既有授权是否覆盖；模型不能自行扩展或恢复已经撤销的授权。

历史查看、结果复用与节点重跑的共同语义见[回溯操作](04-workflow-and-trace.md#3-点击旧节点后可以做什么)。沙盒重跑另外创建隔离环境并校验执行清单。

恢复检查点不能恢复旧权限；在准备阶段和实际调用前都检查授权是否撤销。执行中撤销要取消相关任务并尽力终止后端；界面说明实际停止状态，已经发出的外部请求无法通过撤销本地权限自动收回。

包含外部副作用的工具记录幂等键和执行状态。网络超时导致结果未知时，先核对远端结果；不要把“回溯执行”实现成无条件重试。进程内存或容器快照只有在后端明确支持时才使用，工作流检查点本身不保证恢复进程内存。

## 6. 轨迹应呈现什么

节点轨迹引用执行清单，呈现请求能力、获准能力、后端、代码/输入版本、开始/停止时间、取消、超时、资源超限、输出引用和清理结果。隐藏推理不进入轨迹；凭据和未授权内容在采集时就排除。

建议状态至少区分：`preparing`、`awaiting_approval`、`running`、`cancel_requested`、`cancelled`、`succeeded`、`failed`、`timed_out`、`cleanup_pending`、`sandbox_unavailable`。执行成功和清理成功分别记录，避免节点显示“完成”却仍有后台进程。

“全轨迹”指可以审计执行关系与公开输入输出。大文件、秘密和受限内容显示受控引用或明确的省略原因，不在 UI 或日志中无限量复制。

## 7. 验证顺序与当前缺口

当前只有 [本机可用性探测](../../research/spikes/sandbox-probe/README.md)，未完成真实隔离测试。下列用例是下一阶段验收清单，均不得提前标为通过。

| 阶段 | 验收用例 | 成功标准 |
| --- | --- | --- |
| 后端接入 | 后端未安装、未启动、不支持必需限制、鉴权失败 | 明确拒绝代码节点；没有普通子进程或云端兜底 |
| 文件负测 | 合成的非授权文件、只读输入修改、路径穿越、输出链接 | 请求被拒绝，授权输入仍能读取，宿主合成文件保持原哈希 |
| 网络负测 | 测试域名、直接 IP、IPv6、DNS、宿主服务 | 默认无网络档位均不可访问；使用合成本地/受控目标，不探测用户私网 |
| 资源与取消 | 有限规模 CPU/内存/进程/磁盘/输出压力、取消、主程序异常 | 在限制内停止；没有孤儿进程；环境可清理，失败有记录 |
| 权限与重放 | 审批后修改代码、撤销授权、旧分支恢复、缓存读取 | 修改/撤销不能绕过检查；需要时转为待审批或拒绝 |
| 跨平台交付 | macOS ARM64、Windows x86_64、Linux x86_64 的固定测试环境 | 分别保存版本、配置和结果；不以模拟或文档支持代替实机/CI 验证 |

ARM64 Windows、Intel Mac、企业代理/终端安全软件和远程后端另列兼容范围。MVP 支持哪些组合需要在评审时写清楚。

第一轮实验只需验证一个本地后端和无网络策略；之后再加入有条件网络与远程后端。安全负测通过仅说明这些已测用例符合契约，不等同于没有未知漏洞。
