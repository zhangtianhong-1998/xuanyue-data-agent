# 从“异常”走向有依据的解释

状态：方法设计，未完成真实数据评测。下述算法能力应逐项实现、冻结样例并验证，不承诺仅靠提示词获得“自动根因发现”。

## 分析分层

| 层级 | 回答的问题 | 适用方法 | 结果边界 |
| --- | --- | --- | --- |
| 数据诊断 | 文件是否少了、重复了、口径变了吗 | 完整性、基数、分布、时间覆盖和 join 检查 | 数据异常可能使后续比较失效 |
| 描述变化 | 哪个指标、何时、变化多少 | 同比/环比、分布、分组聚合 | 对比窗口与粒度需一致 |
| 定位贡献 | 哪些群体贡献了变化 | 互斥穷尽分组的 delta 拆解、结构分解 | 描述性贡献，不等于因果 |
| 提出解释 | 价格、销量、结构、渠道等如何关联 | 指标恒等式、漏斗、队列、候选维度搜索 | 结果依赖定义和分解方法 |
| 检验假设 | 候选解释能否被证据支持或反驳 | 分层比较、前后对比、敏感性/反例检查 | 观察性分析仍受混杂影响 |
| 因果研究 | 改变某因素会产生何种效果 | 实验或满足条件的因果设计 | 需识别假设、业务机制和专业复核，后续单独立项 |

## 首版先实现的路径

用户确认问题和口径 → 数据质量检查 → 基期/本期总量 → 选择一个合法维度拆解 → 检查贡献和剩余项 → 用户下钻 → 提出有限候选解释 → 汇总证据与缺口。

对于加法指标，记录 `delta_group = current_group - baseline_group`，在互斥且穷尽的分组中应满足 `sum(delta_group) = delta_total`。若净变化很小或为零，展示变化绝对值和增减抵消，避免失真的贡献百分比。Top-N 之外保留“其他”及其数值。

对于客单价、转化率，必须回到分子/分母；不能平均组比率。去重人数跨组有交集，不能强行相加；库存是时点量，不能直接跨天累加。指标定义要声明加法性和允许聚合维度。

## 复杂洞察如何增加

- 价格 × 数量分解：先由业务确认恒等式与退款口径；不同分解顺序可能分配不同贡献，报告标出采用的方法。
- 转化漏斗：确认事件定义、窗口、去重键和阶段顺序；流失不能自动归因于界面或活动。
- 队列/留存：固定 cohort 定义与观察长度，避免用尚未成熟的 cohort 直接比较。
- 时间序列异常：先检查采样、缺失、节假日和趋势，再选基线；数据不足时不输出伪精确置信度。
- 多维搜索：限制层数、候选数与最小样本；训练/发现集与验证窗口分离，避免扫描大量维度后只报道最显著项。
- Simpson 悖论与结构效应：同时展示总体及分层结果；人群权重变化时单独说明。
- 深度研究：把内部统计结果和外部市场/事件资料分别引用，只把有时间和对象匹配证据的外部解释标为候选。

以上均是未来分析组件的工作要求，尚未进行算法对比或宣称统计有效性。具体方法选型应在拿到领域与样例后查阅原始方法资料并做独立验证。

## 结论的最低结构

每项结论包含：结论类型、适用范围、使用的数据版本、指标口径、查询/分析函数、支持证据、反例或限制、下一步需要什么。复核模型只协助检查遗漏，最终的数值与引用一致性由程序校验。

示例：

> 在已确认的两期订单口径下，销售额由 3000 降至 2600。东区减少 700，西区增加 300，抵消部分下降。可以确认下降集中在东区；当前数据不足以判断是价格、供货还是活动导致。下一步需要东区商品级销量、成交价、退款和缺货记录。

此示例来自本项目合成实验，不代表任何真实企业。
