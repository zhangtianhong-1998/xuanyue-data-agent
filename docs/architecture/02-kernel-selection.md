# Agent 内核选型：AgentScope、LangGraph 与手写

[返回设计入口](../00-discovery-summary.md) · 下一步：[核心对象](03-core-contracts.md)

日期：2026-09-25；状态：**推荐 LangGraph，待用户评审，未批准实施**。本页集中说明取舍；原始运行结果只在[实验页](../research/09-framework-comparison.md)维护。

## 1. 建议及其前提

首版建议采用 **Python + LangGraph 默认流程编排器 + 产品自有协议与服务**。根据新增的多内核需求，允许父 LangGraph 委派给 AgentScope 等子执行器；产品接口分为 WorkflowRuntime、AgentTaskRuntime 和 AgentTransport。业务数据分析作为后续 DomainToolProvider 接入。多内核绑定、切换与 A2A 的详细规则只在[专页](08-runtime-interoperability.md)维护。

主要理由是这次明确的三项核心要求：用户编排可执行流程、进程退出后恢复、从历史节点产生新尝试并保留原轨迹。LangGraph 的检查点、条件边、并行合流和状态分叉能直接承担其中一部分，且本机真实库实验已经覆盖。选择依据是执行语义和需自建的范围，不是 star 数或“功能全家桶”。

AgentScope 同时作为子任务执行器候选和未来完整编排器备选：它的 Agent 循环、消息、工具和事件更集中。若首版改为以自由对话协作为主、只保存当前 Agent 状态，或其稳定发布版把流程历史和分叉机制验证完整，应该重新比较。手写保留为局部协议、策略和适配器实现方式，不建议现在自建完整执行引擎。

## 2. 比较基准与版本

共同场景冻结在 [scenario-v1.json](../../research/spikes/framework-comparison/scenario-v1.json)：文字/图片引用、固定节点与路由、并行、跨进程暂停恢复、历史分叉、拒绝与发布、崩溃去重、公开事件身份。没有真实模型、真实用户文件或性能排名。

- AgentScope：实际运行 **PyPI 2.0.8**，Python 3.11.15；另审阅 main commit `a38821287f35e9e45ed193d9d864cb46f263c946`。main 的版本文件同样写 2.0.8，但 SOP 和 ModelRouter 模块在已安装发布包中不存在。不能混合宣称。[证据](../research/06-agentscope-evidence.md)
- LangGraph：实际运行 **1.2.12 + checkpoint-sqlite 3.1.1**，Python 3.12.13；源码 tag 1.2.12 的 commit `49cce0ca852be4cfb567a1cbe0e511ff325a1682`。[证据](../research/07-langgraph-evidence.md)
- 手写：Python 3.12.13 标准库 + SQLite 固定图。全部行为由应用自写；没有生产执行器、画布编译器或框架 SDK。[实验](../../research/spikes/framework-comparison/handwritten/README.md)

不同 Python 环境、不同实现颗粒度使本轮不适合速度/代码行数比较。通过数量仅用于检查覆盖，不用于机械打分。

## 4. LangGraph 具体承担哪一层

内核分成三层，避免把“选了框架”理解成“内核已完成”：

1. **产品协议和控制服务**：核心对象、授权、预算、事件库、产物、长期画像、分支选择、EffectIntent。由本项目持有，见[核心对象](03-core-contracts.md)。
2. **可恢复调度**：通过 WorkflowRuntime 将已验证 WorkflowDefinition 编译为 StateGraph；调度节点、受限子图与委派节点；持久化与恢复。优先复用 LangGraph。
3. **Agent 与工具适配**：Agent 节点内执行“模型请求 → 结构化动作校验 → 授权/预算 → 工具 → 返回 → 终止或有限次继续”；受管理运行时的 ModelAdapter、MCP、Skill、SandboxProvider 都经过统一控制服务；外部 A2A 服务的内部行为按[接入边界](08-runtime-interoperability.md)处理。

多 Agent 由任务协调器委派独立 AgentTask，不共享可变消息列表，不允许无限递归。受管理执行器建议首版最多两个并发子任务、一级委派；共享父预算，工具权限为父级子集。外部 A2A 服务内部调用不受本地调度器直接控制，只能约束本产品交出的数据、凭据和调用入口，并如实展示其预算/取消承诺。跨内核委派遵循[多内核规则](08-runtime-interoperability.md)，协调器明确等待全部、允许带失败标记的部分结果或取消其余；多个 Agent 同意不能替代证据。

LangGraph state 只存可序列化引用和执行所需数据，不持有数据库连接、容器句柄或密钥。UI 不直接查询框架私有表。运行恢复要固定代码/流程版本并检查兼容；无法迁移时保留只读历史，创建新运行。

## 5. 为什么不先手写完整执行器

手写实验用较少代码就通过固定用例，说明机制可实现，不说明产品工作量小。尚未覆盖的部分包括：用户动态图编译、节点与子图重放、并发写入、事件断点续传、流式模型中断、版本迁移、共享预算、插件生命周期和跨平台进程管理。个人研发优先把时间放在产品契约和交互上更合适。

此前“K1 不加入双内核”的限制已按新增需求撤回。现在采用分层委派：父编排器、子执行器分别拥有局部状态与重试，委派服务负责身份和恢复核对。混合使用不意味着两个内核都能编译同一完整工作流，也不意味着原生检查点可以相互转换。

## 6. 接受建议前要明确的代价

- 这是**机制实验支持的建议**，未验证真实模型路由质量、完整多 Agent 协作、子图任意内部节点回溯或三系统发行。
- LangGraph 的 reducer 与分叉写入语义要由适配器控制；用户不能直接编辑任意 state 字段。当前实验覆盖输入与一个中间检查点分叉，没有穷举所有检查点。
- MCP SDK 要单独规划版本。AgentScope 2.0.8 锁 `mcp<2`，本仓库旧 MCP 实验为 2.2.0，不能把两个环境直接混装。这是依赖兼容问题，不能推断协议全面不兼容。
- 沙盒仍是单独决策。本机当前没有可连接的容器 daemon，隔离负测尚未执行。

建议评审结论为“LangGraph 作为 K1 默认编排候选、支持多内核子执行器、统一协议由产品持有、先交付内核工作台”。真实模型和沙盒验收通过后，再确认发行路线。若 K1 出现无法控制的历史/取消/迁移缺陷，保留改用 AgentScope 或缩小手写执行器的退出路径。
