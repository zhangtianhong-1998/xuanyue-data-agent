## 需求与待决问题

同一产品中，由 LangGraph 或 AgentScope 运行的 Agent 都应能成为一次任务的**主 Agent**：接收目标、维护自己的执行状态、委派和观察子 Agent、汇总结果，并通过统一界面呈现。用户创建自主任务时选择主内核；编排确定性工作流时也指定主 Agent 及其内核。工作流步骤可以固定，但主 Agent 仍可按流程派发子 Agent。运行后固定绑定；下一项任务或新流程版本可以改选，旧运行仍保留原绑定。混合父子至少要分别检查 LangGraph 主→AgentScope 子、AgentScope 主→LangGraph 子。

**谁担任主 Agent，由用户决定：自主任务创建时选择，确定性工作流编排时选择。** 固定流程由产品自有调度层运行，还是由框架的工作流适配器运行，是另一项待评审的技术选择。调度层只负责既定步骤及状态，必须遵从流程版本中保存的主 Agent 配置，不可成为它的替身。能力检查不通过时应说明原因并停止，不得暗中改用另一种内核。AgentScope 的历史节点分叉尚未验证；两个框架能否完整执行同一固定流程另需实验。

产品持有会话、规范消息、任务/产物身份、授权、预算和公开事件的设计方向可以继续评审。A2A 是跨进程委派的候选传输，不自动提供内部全轨迹、状态迁移或可靠去重。任务运行后固定所选绑定；原生检查点跨内核可移植性仍需单独验证。具体契约以重审后的[多内核设计](../08-runtime-interoperability.md)为准。

## 本轮阶段门

1. 先核对需求及文档：分别写清主 Agent、工作流调度器、子 Agent、传输层的责任；列出两种主 Agent 的等价操作与可见差异。本阶段不启动完整产品实现。
2. 下一轮针对未验证的 AgentScope 主→LangGraph 子，以及 AgentScope 单独担任主 Agent 的任务生命周期、补充输入、恢复和取消做合成实验；与已有 LangGraph 主→AgentScope 子的实验按同一契约比较。失败和不支持项保留。
3. 根据双向证据评审自主任务的双主内核接入，再决定实现阶段。独立确定性工作流的调度责任、画布和交付范围另行评审；节点历史分叉也单列验收，不把任务级主 Agent 切换冒充完整工作流互换。

当前证据：[框架对照](../../research/09-framework-comparison.md)和[单向 A2A 委派实验](../../../research/spikes/runtime-interoperability/README.md)。两者尚未完成上述双主 Agent 验收；本 ADR 是待评审的需求落实方案，不是已批准选型。
