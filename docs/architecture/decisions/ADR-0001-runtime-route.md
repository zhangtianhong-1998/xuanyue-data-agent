# ADR-0001：桌面外壳、Agent 运行时与分析层分离

- 日期：2026-09-24
- 状态：Proposed（待用户评审）
- 对应故事：US-007、US-009–019、US-024–031

## 背景

需要本地文件分析、丰富图表和现代 Agent 扩展，同时支持三种桌面系统。当前由用户与 Codex 协同开发个人版本。团队规模和安全边界不适合同时构建企业后端、多个执行框架及完整办公应用。

## 候选

1. Electron + React/TypeScript + Python/LangGraph + DuckDB。
2. Tauri 2 + React/TypeScript + Python/LangGraph + DuckDB。
3. 全 TypeScript 内核与本地分析适配。
4. 整体 fork 某个已有桌面 Agent，直接增加 BI。

## 建议决定

优先验证候选 1。保留受限 IPC 与业务契约，减少桌面外壳、模型供应商与计算层相互依赖。参考上游设计，暂不整仓 fork。候选 2 作为实际资源限制出现后的对照方案。

依据见 [候选架构](../01-candidate-architecture.md) 与三份研究报告。SP-01/02 仅覆盖查询契约和执行语义；桌面分发、真正的模型行为和 UI 均未验证。

## 代价与后续工作

- Python 分发需要逐 OS/架构构建与测试。
- Electron 资源开销必须实测；Linux 更新需专门设计。
- 多 Agent/权限/证据/恢复并不会因为选用框架而自动完整，需要产品层实现。
- 下一步先做 SP-03/04/05，再建立正式应用工程。若实验不通过，修改本 ADR 后重新评审。
