# 产品需求与阶段范围

[返回设计入口](../00-discovery-summary.md) · [用户故事](02-user-stories.md)

日期：2026-09-25；状态：用户目标已确认，技术路线与各阶段的实现方案待评审。

## 已确认的目标

做一个 macOS、Windows、Linux 上运行的 Data Agent 客户端，先在当前 Mac 开发个人版本。首个业务场景仍是经营数据分析：导入文件、发现异常、下钻、形成有来源的报告。数据默认保存在本地，必要内容经授权发送给云模型。

**先验证 Agent 内核，再接入完整 Data 功能。**内核需要多 Agent、可编辑混合工作流、长期用户画像、统一多模态消息、全轨迹与历史分叉、MCP/Skills 和执行沙盒。LangGraph 与 AgentScope 都必须能够担任主智能体；用户可选择主智能体内核，父子 Agent 也可使用不同内核。研究 A2A 作为父子协作协议。后续本体/语义层服务只留接口，不在本项目实现。

这里的“主智能体”指一次用户任务中接收目标、推进计划、发起委派并组织结果的 Agent 角色。工作流调度、状态存储、权限与事件可以由产品自有层承担，具体实现待验证；选择 AgentScope 为主智能体时，不能在背后仍让 LangGraph 父 Agent 主持该任务。两种主智能体需要达到同一组首版必需行为，不能靠隐藏能力缺口宣称无感切换。

## 内核 MVP 的目标使用场景

用户选择 LangGraph 或 AgentScope 作为主智能体，建立任务并选择或编辑一个流程：固定工具处理输入 → 小模型选择路径 → 两个 Agent 分别完成子任务 → 用户检查 → 保存产物。过程中可以查看所有公开步骤、停止、关闭后恢复。对不满意的结果，从历史节点改参数或模型重新运行，比较两个尝试，选定一个；旧记录仍可查看。系统使用可查看和纠正的项目偏好，生成代码经沙盒执行。两种主智能体都应能委派任务；跨内核委派需要分别验证 LangGraph 主→AgentScope 子和 AgentScope 主→LangGraph 子。界面和产物入口一致，能力不足、出网变化和恢复限制仍如实提示。

先用合成工具和材料验证这条路径，避免把指标算法、BI 组件和内核缺陷混在一起。随后将工具替换为数据导入、查询、图表和分析方法，保持同一套运行与权限协议。

## 分期建议

| 阶段 | 交付与验收 | 此时不承诺 |
| --- | --- | --- |
| K0a 需求纠偏（本轮） | 修正双主智能体目标、共同验收和文档关系；标出既有证据只覆盖的方向 | 已选定调度层或已实现双主内核 |
| K0b 下一实验门槛 | 以已有单向实验为基线，用一致的合成任务补验 AgentScope 主运行和 AgentScope 主→LangGraph 子委派；需要时复跑 LangGraph 主运行以保证对照条件一致，保留失败与能力缺口 | 双向能力已具备产品级可靠性 |
| K0c 路线评审 | 根据 K0b 结果比较产品自有工作流调度层、两个主内核适配器等方案，记录取舍与尚需解决的缺口 | 未评审就确定单一默认主内核 |
| K1a 双主内核可运行版本 | 两种内核分别接收并推进同一固定任务，完成规范消息/事件、受限委派、持久恢复、权限预算和产物保存；双向跨内核委派有可复核结果 | 面向普通用户的完整客户端 |
| K1b 内核工作台 MVP | 同一界面选择两种主内核、编辑混合流程、查看轨迹并从历史节点分叉比较；接入真实模型、本地 MCP/Skill、画像管理和真实沙盒后端，逐项验收 | 全功能 BI、真实路由质量已达标或三平台已自动兼容 |
| D1 首个业务版本 | CSV → 口径确认 → 本地计算 → 异常/贡献 → 图表下钻 → 来源报告；各目标系统分别验收 | 完整根因发现、全部文件格式 |
| D2 扩展分析 | XLSX/Parquet、多表、版本更新、复杂诊断、实际视觉材料分析 | 无条件因果定论 |
| X 按需扩展 | 更多 A2A 服务/版本、远程 MCP、TTS、深度研究、语义层对接、更多连接器 | 本轮开发本体服务或企业多租户 |

每过一道门槛先展示证据、失败和待定项，再决定下一步；K0b 实验不能直接升级为 K1 产品代码。K1 指 K1a 与 K1b 的合并范围，可拆为多次小交付；只有两种主智能体在共同必需行为上通过验收，才能称双主内核 MVP。K1 在开发 Mac 验证并建立跨平台测试入口；只有三端安装/运行实测通过，才称跨平台版本。多模态消息协议在 K1 固定，实际识别能力按适配器逐项验收。

## 非功能要求

所有阶段都要求：凭据不进轨迹；权限不随模型输出扩大；取消、失败、未知和部分完成有明确状态；历史输入与产物可定位；费用未知时标未知；代码、流程和依赖版本可记录与复现。最终用户不应为运行客户端自行配置 Python/Node，但沙盒后端是否需要额外安装是待评审取舍。

数据规模、性能与模型质量不能从小样本实验推断。D1 再固定业务样例、指标答案与规模档位；K0b 先固定双主运行的合成场景与失败标准，K1 再固定产品执行语义、路由标签集和故障注入场景。多内核与无感切换的范围见[多内核设计](../architecture/08-runtime-interoperability.md)。具体规则见[研发流程](../engineering/01-development-process.md)。
