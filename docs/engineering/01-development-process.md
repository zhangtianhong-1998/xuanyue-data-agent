# 研发流程与文档维护

[返回设计入口](../00-discovery-summary.md)

日期：2026-09-25。当前是 K0a 需求纠偏；阶段范围只在[产品需求](../product/01-product-brief.md)维护。

## 1. 按可演示的行为推进

每个阶段走同样的流程：选择故事 → 明确输入/输出和失败行为 → 必要的界面草图与契约 → 小范围实现 → 验证 → 用户演示 → 记录结果。不要把所有文档写完才开始一个大版本，也不要把研究脚本直接改名成产品内核。

路线、成本、用户体验、安装依赖或权限范围的重大取舍交给用户；日常编码、修复和验证由研发完成。ADR 的 proposed 只有在评审后改为 accepted；需求改变时保留变更原因，不把旧建议伪装成已批准决定。

目录遵循 AGENTS.md：产品/架构/研究/工程分开；apps、packages、tests 在方案批准前只有边界说明。后续按实际需要增加模块，不先搭大量空包或微服务。

## 3. 每道门槛只回答一个范围的问题

| 门槛 | 工作 | 交付给下一次评审的证据 |
| --- | --- | --- |
| K0a 当前 | 按已确认的双主智能体需求纠正文档与故事 | “主智能体”和“工作流调度器”职责分开；LangGraph 与 AgentScope 都是主运行候选；现有单向实验的边界清楚 |
| K0b-1 下一步 | 独立 AgentScope 主运行合成实验；必要时复跑 LangGraph 主运行，统一对照场景 | AgentScope 不经隐藏的 LangGraph 父 Agent 接收并推进任务；记录委派、暂停/恢复、取消、公开事件、产物和历史分叉是否可行，保留失败与不支持项 |
| K0b-2 下一步 | AgentScope 主→LangGraph 子的 A2A 实验，与已有反向实验对照 | 两向任务关联、等待输入、未知提交、终态、能力缺口、产物和轨迹范围；单向通过不推断双向成立 |
| K0c 路线评审 | 用同一验收表比较产品自有工作流调度层、双主内核适配等候选 | 逐项解释能力缺口、应用自建代码、维护成本与用户体验；评审后再更新 ADR，不由某个实验通过直接指定默认主内核 |
| K1a 可运行版本 | 按选定路线实现规范对象与两种主运行的固定流程 | 分支身份、事件持久化、新进程恢复、故障与去重；按 US-043–050 验证双主和双向委派 |
| K1b 工作台 MVP | 按[阶段范围](../product/01-product-brief.md#分期建议)分批接入模型、扩展能力、沙盒和界面 | 实际费用/延迟、权限预算、沙盒负测、编辑→试跑→分叉→比较、画像管理及桌面进程与发行预检分别记录 |

K0b 仍是可复现研究实验，不以合成流程通过宣称产品可用。每道门槛先提供结果、失败和待定项，再讨论下一步；路线评审完成前不搭建完整内核工作台。可交叉推进独立的低保真页面。真实模型测试前确定供应商与预算，不需要将密钥写进仓库。Data 图表交互和大文件性能移到 D1；不取消其验收。

## 4. 测试与证据

工程、路由/Agent 质量、画像效果、数据计算、UI 可用性、安全和跨平台各自报告。测试输入/答案/容差先冻结；保留失败、跳过和未判断；不能修改答案换取通过。模拟模型证明执行机制，真实模型证明该样本集上的行为；均不能外推所有业务场景。

有副作用的故障注入用合成接收方；记录预设退出码、尝试次数和实际写入次数。升级依赖或修改执行语义后重新跑相关用例。结果绑定脚本与锁文件哈希，新脚本不冒用旧结果。

## 5. Git 与发布

设计与自编实验一并提交。新开发分支默认 `codex/<topic>`；小提交写清行为、对应故事与验证。第三方源码只记录固定 commit/根许可证哈希/获取脚本，依赖环境、业务数据、密钥、运行数据库和构建产物不提交。主项目许可证仍待用户确定。

公开前检查新增文件、凭据模式、个人路径和产物来源；保留可复现的失败但处理本机路径。上传后核对远端可见性、分支、commit、文件范围和本地工作区。公开仓库不等于已承诺开源许可证或正式产品发行。
