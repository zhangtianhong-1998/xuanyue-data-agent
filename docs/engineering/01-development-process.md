# 下一步怎么做

[阅读入口](../00-discovery-summary.md) · [产品目标与阶段](../product/01-product-brief.md#分期建议) · [实验索引](../../research/spikes/README.md)

状态：需求与技术路线评审中。这个项目按一个能演示的小目标往前走。每一步都留下可读的结论、代码和失败记录，再决定下一步。

## 现在做到哪里

现有实验已经证明：LangGraph 可以运行一个固定流程并在指定位置恢复；AgentScope 的 Agent 循环、工具和部分状态操作能运行；LangGraph 主任务可通过 A2A 调用 AgentScope 子任务。这些是局部工程结果。**AgentScope 独立担任主任务、反向委派和双主工作流切换还没有验证。** 具体输入、版本、失败和限制都从[实验索引](../../research/spikes/README.md)进入。

本轮先整理仓库和文档：让新读者知道目标、当前结果、未决问题和下一实验。研究报告和技术字段继续保留，放在需要查证时打开的位置。

## 一次标准开发循环

1. **写清用户要做的事。** 例如“换成 AgentScope 主智能体后，仍能查看任务进度并继续等待原子任务”。在[故事表](../product/02-user-stories.md)写出成功、失败和不支持时各会看到什么。
2. **列出已有证据和未知点。** 官方文档说支持什么、本机到底跑过什么分开记录。没有跑过的行为写“未验证”。
3. **做最小实验。** 固定框架版本和合成输入，只验证眼前一个风险。保留首次失败、修正后的代码、结果和运行命令。
4. **比较实现做法。** 看用户体验、需要自写的代码、恢复与升级风险。大方向写入 ADR；`Proposed` 表示仍在讨论，`Accepted` 才是选定路线。[决策索引](../architecture/decisions/README.md)区分当前提案和历史提案。
5. **做一个可演示的功能。** 契约、代码、必要测试和说明放在同一个小改动里。实验脚本不能直接当产品内核。功能完成后按故事逐项验收。
6. **请用户看实际行为。** 展示任务怎样运行、哪里失败、哪些代价还不知道。讨论后的修改进入下一轮，不把整套产品一次做完。

路线、安装依赖、费用和权限范围等重大取舍交给用户评审；常规实现、修复和验证由研发继续完成。

## 接下来的两个小实验

**实验一：AgentScope 独立做主智能体。** 用合成模型和工具，让它接收目标、给出公开计划、委派一项任务、等待用户输入、停止和恢复。记录实际运行的进程与框架调用，确保背后没有 LangGraph 父任务代替它决策。给出消息、状态、事件和产物；历史节点分叉单独写通过、失败或不支持。

**实验二：反向 A2A 委派。** AgentScope 主任务调用 LangGraph 子任务。用已有 LangGraph 主→AgentScope 子实验的相同类型输入，核对父子身份、等待输入、取消、产物、断线及重复提交。一个方向通过，不自动算另一个方向通过。

两项结果齐备后，再比较“产品自己调度用户流程”和“两套框架分别适配工作流”。比较结果写入新的评审记录，然后进入内核实现阶段。阶段划分只在[产品目标](../product/01-product-brief.md#分期建议)维护。

## 文档和代码怎么放

| 需要找什么 | 去哪里 |
| --- | --- |
| 产品目标、用户故事 | `docs/product/` |
| 当前内核设计、对象字段和架构决策 | `docs/architecture/`；旧 ADR 从[索引](../architecture/decisions/README.md)辨认 |

README 给第一次来的人看；一篇主题文档只回答一个问题。字段表、协议细节和负测保留在技术参考页，主文章给出具体例子和链接。当前需求、待评审方案、已测事实和历史提案要明确标注。提交前检查相对链接、章节、故事编号与阶段描述。文档本身也按 [US-051](../product/02-user-stories.md#9-仓库与文档) 验收。

## 验证与 Git

工程机制、模型质量、数据正确性、界面、沙盒和三平台安装分别报告。先固定输入和期望结果，保留失败、跳过及未判断；不能为了通过而改答案。合成模型证明执行步骤，真实模型还要单独评估效果、费用和延迟。有副作用的故障注入先用合成接收方，记录实际重试次数和写入次数。

设计文档与自编实验一起提交。新分支默认用 `codex/<topic>`；提交说明写清改变了什么。公开仓库只包含自己的文档、代码、锁文件和合成结果，不放第三方整仓、依赖环境、业务数据、密钥和运行数据库。发布前查文件范围与凭据；推送后核对仓库可见性、远端提交和本地工作树。项目许可证仍待确定。详细约束见[AGENTS.md](../../AGENTS.md)。
