修订：2026-09-27；状态：本机开发预览，项目与会话重命名切片待审。当前界面允许新会话选择主内核与已登记模型，发送文字时可附一张图片。它不提供经营数据分析，也没有完成桌面安装包。

## 用户现在能做什么

本机只有一个“本机用户”。这个用户可以创建多个项目，每个项目创建多个会话，并在左侧重命名它们。改名后，已有会话、主内核、模型和问答记录都保留。创建会话时选择 AgentScope 或 LangGraph 作为主内核，也可从本机配置中选择模型；后续提问沿用这两个选择。左侧切换项目和会话，中间查看问答并继续提问；执行轨迹视图展示所选运行的公开事件、工具参数、工具返回和失败状态。项目和会话的删除尚未实现。

模型先在 `xuanyue.toml` 中登记，密钥留在环境变量或同目录 `.env`。[配置字段与示例](03-dual-kernel-and-model.md#配置真实模型)只在一处说明。新建会话时，模型列表显示登记 ID、配置是否就绪、目标域名和图片输入开关；“已配置”不代表服务连通或模型接受当前任务。选中后模型 ID 保存到会话。未写 `model` 的旧请求仍使用默认项。显式选择的模型若已从配置删除，请求会失败，不会改用默认模型。界面目前不能新增或修改供应商。

界面调整后，项目和会话仍在左侧；空会话显示欢迎语与输入框，有历史的会话直接显示问答。执行轨迹从顶部视图按钮或每轮答复下方的入口打开，事件按顺序排列，输入输出详情可展开。窄窗口中，项目导航收进菜单。根据审阅意见，侧栏去掉了没有操作的本机身份卡和开发版说明，对话改用文字区分角色，并移除输入框下方常驻的模型服务说明；模型不可用时仍显示错误提示。这只是现有功能的呈现方式调整，交互边界见下文。

当前 OpenAI 兼容模型服务返回文字增量时，AgentScope 和 LangGraph 都会逐块记入公开轨迹；页面运行中约每 400 毫秒读取一次已保存事件，并逐步显示回复。工具返回后，上一轮模型的临时文字不作为最终答案；整轮完成时只显示经服务确认的答案。网络流中断或供应商没有发出合法结束标记时，运行记为失败，部分文字仍留在轨迹供排查。轨迹列表把连续文字片段收成一行，展开可看每条原始事件。图标缩小并去掉了多数装饰底色。

项目、会话、每轮问题与答复、公开事件保存在本机 SQLite；图片写在数据库旁的本机私有附件目录，数据库只保存引用和元数据。关闭界面再打开，已保存的内容仍可查看；一轮运行完成后，下一轮会带上该会话此前**已完成的文字问答及所附图片**。失败或中断的运行仍可查看，但不会进入后续提问的历史。旧工具记录用于查看，目前不作为后续模型的上下文重放。

界面展示的是**公开执行记录**：输入的问题、框架适配器提供的模型与工具事件、可见答复和安全的失败类别。当前内核没有提供公开计划、准确费用或完整模型输入事件。模型隐藏推理不采集，也不显示；界面不会替模型编造“思维链”。

## 图片输入这一段

会话所选模型在本机配置中明确写有 `image_input = true`，图片按钮才可用。用户先输入文字，再选一张 PNG 或 JPEG；单张不超过 5 MiB。界面会预览待发送图片，也可移除；发送后可在问答里打开图片查看。发送时先上传原始文件，再用附件 ID 创建本轮运行；两种主内核收到的顺序都是文字在前、图片在后。图片只在模型请求的内存中转成 Chat Completions 所需的 data URL；公开事件与数据库不保存 base64。上传后若创建运行失败，界面请求删除未绑定的附件；服务重启时也会清理未绑定的附件和孤立文件。已绑定运行的图片不会被这项清理删除。

图片附件只可从所属项目读取；完成的图文轮次可在下一轮作为历史再交给同一模型。如果会话模型的图片开关后来关闭，含历史图片的下一轮也会被拒绝。文件类型目前只核对请求类型与文件头，不做完整图像解码。`image_input` 只是本机配置声明：产品不会探测供应商视觉能力，也不会在发图失败时自动换模型或主内核。当前只支持**文字加一张输入图片**；图片生成、PDF、音视频、图片内容理解质量，以及火山兼容入口的真实视觉效果都未验收。长会话会反复发送此前完成轮次中的图片；本切片不会悄悄省略历史图片，累计内存、延迟与费用上限尚未评估。

## 在 Mac 开发环境启动

在仓库根目录安装依赖，并按[模型配置说明](03-dual-kernel-and-model.md#配置真实模型)准备本机 `xuanyue.toml` 和 `.env`。两者不会进入 Git。以下命令都从仓库根目录运行：

```bash
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python -e '.[agentscope,langgraph,live-model]'
npm --prefix desktop ci
npm --prefix desktop run build
.venv/bin/xuanyue-app
```

服务默认监听 `127.0.0.1:8787`，数据库默认写到被 Git 忽略的 `runtime/xuanyue.sqlite3`。浏览器可打开 `http://127.0.0.1:8787/`。保持服务终端运行，在仓库根目录的另一终端执行 `npm --prefix desktop run desktop`，可在 Electron 开发窗口中打开同一页面。Electron 当前固定访问 8787 端口。修改前端时可从仓库根目录运行 `npm --prefix desktop run dev`，Vite 将 `/api` 请求转到本机服务。`.venv/bin/xuanyue-app --help` 可查看数据库、配置、端口和静态目录参数。

如果提示“同一数据库已被另一个玄月实例使用”，先检查是否已有服务在运行；可继续使用它，或在它的终端按 `Ctrl+C` 关闭后重启。并行运行两个服务时必须分别指定 `--db`。如果提示 8787 端口已被占用，需要先关闭占用端口的服务再启动当前服务；Electron 开发窗口只会连接 8787。

每次按“发送”，本轮文字、所附图片和已完成的问答历史会交给配置的模型服务。界面在模型不可用时说明原因；已完成运行的轨迹列出当时的模型 ID。密钥由 Python 后端读取，不返回给前端。这个预览只绑定回环地址，并限制请求来源；它尚未接入正式桌面宿主的进程监管、随机端口和凭据传递，也没有多用户登录。[桌面安全与分发候选](../research/03-desktop-and-delivery.md#3-进程与数据传输边界)保留了后续需要验证的边界。

## 代码和数据边界

| 位置 | 当前职责 |
| --- | --- |
| [`storage.py`](../../src/xuanyue/storage.py) | 保存本机用户、项目、会话、运行、公开事件和图片附件引用；读取完成的图文历史 |
| [`chat.py`](../../src/xuanyue/chat.py) | 列出安全的模型摘要，按会话绑定的内核与模型执行一轮，先保存事件再更新终态 |
| [`server.py`](../../src/xuanyue/server.py) | 向本机界面提供项目、会话、重命名、图片上传与读取、运行记录接口 |
| [`desktop/`](../../desktop/) | React 界面与仅供开发的 Electron 窗口，不直接读取框架对象或密钥 |

数据库和真实对话放在本机，不纳入 Git。事件按 `(run_id, seq)` 排序；界面重取运行记录时依据已保存内容显示，不把尚未收到的事件假装成完成。服务异常退出后的运行标为中断，原事件保留；用户可以在会话中发起**新一轮**，目前不能从旧 Agent 节点继续原运行。

## 这段尚未覆盖

- 未实现账号登录、多人隔离、经营数据文件导入与分析。当前图片只是模型对话附件，数据库保留用户、项目、会话关系，但当前只有本机用户。
- 项目与会话可重命名，尚不能删除。删除还需处理运行中的任务、历史事件和图片附件；这部分会作为独立切片验收。
- 未实现原生内核检查点、旧节点回溯、派生分支、运行中取消或退出后续跑。[目标交互](../architecture/04-workflow-and-trace.md#3-点击旧节点后可以做什么)仍须单独实验和评审。
- 当前工具只有原来的纯计算样例；没有 MCP、沙盒或用户可设置的工具权限。公开事件的范围取决于框架适配器实际给出的内容。
- Electron 只作 Mac 上的开发窗口；Windows、Linux 安装、签名、后台进程管理和资源占用未验收。
