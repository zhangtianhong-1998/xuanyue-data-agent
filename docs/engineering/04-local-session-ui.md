修订：2026-10-05；状态：本机开发预览，长历史修复待审。当前界面允许创建、重命名、删除项目和会话，新会话可选择主内核与已登记模型。它不提供经营数据分析，也没有完成桌面安装包。[代码审查](../research/12-code-design-review-20261003.md)复现了长历史、工具异常和调用事件的三处偏差；长历史已在产品模型入口做合成修复，另外两项未修复。

## 用户现在能做什么

本机只有一个“本机用户”。Mac 桌面版点击“新建项目”会直接打开系统目录选择器，选定后以文件夹名称创建项目；网页预览需输入本机已有文件夹的绝对路径，项目名同样取自文件夹。展开项目后，右侧的加号用于新建会话；省略号或右键打开重命名、删除菜单。创建会话时选择 AgentScope 或 LangGraph 作为主内核，也可从本机配置中选择模型。首次成功答复后，会话标题由同一模型生成；改名后自动标题不会覆盖用户输入。

侧栏底部的“模型设置”可登记供应商接口和模型、选择默认模型、填写新密钥；新会话弹窗里也有入口。设置页不显示已有密钥，只显示是否配置。新会话用可搜索菜单选择主内核与模型，方向键、Enter 和 Escape 可操作；模型列表显示名称、供应商与配置状态。选中后模型 ID 保存到会话；两轮之间可从输入框右下角切换模型与该模型的推理选项，历史回复仍展示当时的选择。当前只接入 OpenAI Chat Completions 兼容协议，原生 Claude Messages 尚未接入。[配置字段、保存位置与限制](03-dual-kernel-and-model.md#配置模型并在会话中切换)集中说明。

空会话显示欢迎语与输入框，有历史的会话直接显示问答。每轮回复旁显示用时和公开执行过程：运行中自动展开，结束后默认收起；展开后查看模型调用，以及有明确关联的工具输入与返回。原始事件留在顶部“执行轨迹”视图。右侧短刻度按轮次排列，点击可跳到对应提问；刻度位置不代表用时。窄窗口中，项目导航收进菜单。

当前 OpenAI 兼容模型服务返回文字增量时，AgentScope 和 LangGraph 都会逐块记入公开轨迹；页面运行中约每 400 毫秒读取一次已保存事件，并逐步显示回复。工具返回后，上一轮模型的临时文字不作为最终答案；整轮完成时只显示经服务确认的答案。网络流中断或供应商没有发出合法结束标记时，运行记为失败，部分文字仍留在轨迹供排查。

项目、会话、每轮问题与答复、公开事件保存在本机 SQLite；图片写在数据库旁的本机私有附件目录，数据库只保存引用和元数据。关闭界面再打开，已保存的内容仍可查看；一轮运行完成后，下一轮会带上该会话此前**已完成的文字问答及所附图片**。失败或中断的运行仍可查看，但不会进入后续提问的历史。旧工具记录用于查看，目前不作为后续模型的上下文重放。

界面展示的是**公开执行记录**：输入的问题、框架适配器提供的模型与工具事件、可见答复和安全的失败类别。当前内核没有提供公开计划、准确费用或完整模型输入事件。模型隐藏推理不采集，也不显示；界面不会替模型编造“思维链”。

## 工作文件夹与删除

新建项目要选择本机**已有文件夹**。Mac 的 Electron 开发窗口直接打开系统选择器，首次从桌面开始，之后从上次选择的同级目录开始；浏览器预览仍需手填绝对路径。两种入口都用目录名称作为项目名。服务核对路径存在且为目录，再保存规范路径。旧项目若原本没有工作文件夹，仍可查看。**登记路径只让项目记住位置，不会扫描文件夹，也不授予 Agent 读取或写入文件的权限。**本机实测选择器从点击到出现约需 1.1–1.8 秒，选定后约 0.86 秒显示项目；服务路径校验约 0.01 毫秒。因此当前等待主要发生在系统选择器启动，换起始目录和减少表单步骤不能让它瞬间出现。[Electron 官方说明](https://www.electronjs.org/docs/latest/api/dialog)列出 `defaultPath` 行为；这些耗时只代表本次 Mac 开发机测量。

删除前，界面会列明影响并要求确认。删除会话会清除它的运行与公开事件，以及不再被其他会话引用的图片附件；删除项目会清除其全部会话、运行、事件和本机图片附件。**所选工作文件夹及其中的文件不会被删除。** 项目或会话仍有运行中任务时，服务以 409 拒绝删除，用户需等任务结束再操作。

通常删除完成后接口返回 204。若数据库记录已删除、附件文件却未能清理，接口返回 202；界面仍移除已删除记录，并保留“附件文件清理待重试”的提示。服务会在后续删除或重启清理时重试。202 不表示附件文件已清理完，也不应重复删除已不存在的项目或会话。

## 首轮自动标题

新会话先显示“新会话”。首轮成功答复保存后，产品用该会话绑定的模型额外请求一次标题；请求只带本轮问题和答复各最多 600 字，超时为 8 秒。成功后侧栏和顶部标题更新；失败时保留“新会话”，用户可手工改名。标题请求不改变主智能体内核，也不计入 Agent Run 的用时或公开轨迹；目前没有单独展示该请求的用量和费用。

## 图片输入这一段

会话所选模型在本机配置中明确写有 `image_input = true`，图片按钮才可用。用户可在输入框粘贴图片，或点击图片按钮一次选多张 PNG/JPEG；每轮最多四张，每张不超过 5 MiB。输入的问题文字仍必填。界面按加入顺序预览图片，可逐张移除；发送后可在问答里逐张打开。发送时先依次上传原始文件，再用有序的附件 ID 列表创建本轮运行。两种主内核收到的顺序都是文字在前、图片依次在后。图片只在模型请求的内存中转成 Chat Completions 所需的 data URL；公开事件与数据库不保存 base64。上传中途或创建运行失败时，界面逐张请求清理已经上传但尚未绑定的附件；服务重启时也会清理未绑定的附件和孤立文件。已绑定运行的图片不会被这项清理删除。

图片附件只可从所属项目读取；产品按原顺序把完成的图文轮次交给下一轮主内核。如果会话模型的图片开关后来关闭，含历史图片的下一轮也会被拒绝。文件类型目前只核对请求类型与文件头，不做完整图像解码。`image_input` 只是本机配置声明：产品不会探测供应商视觉能力，也不会在发图失败时自动换模型或主内核。当前只支持**文字加最多四张输入图片**；纯图片消息、图片生成、PDF、音视频、图片内容理解质量，以及火山兼容入口的真实视觉效果都未验收。原版 AgentScope 在合成长文字历史中会静默截断；[A1 修复](05-code-review-remediation.md#a1-的实际结果2026-10-05)已用八轮文字和六张跨轮图片核对产品模型接口收到的完整输入。真实供应商容量、累计内存、延迟与费用上限尚未评估。

## 公开调用关联这一段

用户展开一轮回复时，可以从模型调用看到工具调用、输入和返回。AgentScope 与 LangGraph 在公开事件里给每次模型调用和工具调用分配本轮唯一的 `activity_id`；工具事件还保存发起它的模型调用 ID `parent_activity_id`。界面只按这些明确的 ID 关联，不凭事件相邻、答复文字或工具名称推断父子关系。模型调用在工具执行前结束，工具返回仍挂在发起它的那次调用下。关联关系在已测成功回合成立；LangGraph 达到循环上限时曾多记一次未发生的模型调用开始事件，尚待修复。

旧运行没有这些 ID，界面将其标为“旧记录缺少关联信息”，保留可查看的公开事件，不把它们伪装成准确的调用树。事件缺失、无法关联或框架覆盖缺口也会提示。这里的层级只说明**运行 → 模型调用 → 工具调用**；产品还没有分析步骤、文件读取、Skill、子智能体的真实事件，不能展示它们的路径，也不采集模型隐藏推理。事件仍按 `(run_id, seq)` 持久化；本段没有增加运行恢复或从旧节点分叉能力。

## 在 Mac 开发环境启动

在仓库根目录安装依赖，并按[模型配置说明](03-dual-kernel-and-model.md#配置模型并在会话中切换)准备本机 `xuanyue.toml` 和 `.env`。两者不会进入 Git。以下命令都从仓库根目录运行：

```bash
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python -e '.[agentscope,langgraph,live-model]'
npm --prefix desktop ci
npm --prefix desktop run build
.venv/bin/xuanyue-app
```

服务默认监听 `127.0.0.1:8787`，数据库默认写到被 Git 忽略的 `runtime/xuanyue.sqlite3`。浏览器可打开 `http://127.0.0.1:8787/`。保持服务终端运行，在仓库根目录的另一终端执行 `npm --prefix desktop run desktop`，可在 Electron 开发窗口中打开同一页面。Electron 当前固定访问 8787 端口。修改前端时可从仓库根目录运行 `npm --prefix desktop run dev`，Vite 将 `/api` 请求转到本机服务。`.venv/bin/xuanyue-app --help` 可查看数据库、配置、端口和静态目录参数。

如果提示“同一数据库已被另一个玄月实例使用”，先检查是否已有服务在运行；可继续使用它，或在它的终端按 `Ctrl+C` 关闭后重启。并行运行两个服务时必须分别指定 `--db`。如果提示 8787 端口已被占用，需要先关闭占用端口的服务再启动当前服务；Electron 开发窗口只会连接 8787。

每次按“发送”，本轮文字、所附图片和已完成的问答历史会交给配置的模型服务。界面在模型不可用时说明原因；新运行的轨迹展示当时保存的模型名称；旧记录没有名称时显示模型 ID。密钥由 Python 后端读取，不返回给前端。这个预览只绑定回环地址，并限制请求来源；它尚未接入正式桌面宿主的进程监管、随机端口和凭据传递，也没有多用户登录。[桌面安全与分发候选](../research/03-desktop-and-delivery.md#3-进程与数据传输边界)保留了后续需要验证的边界。

## 代码和数据边界

| 位置 | 当前职责 |
| --- | --- |
| [`storage.py`](../../src/xuanyue/storage.py) | 登记工作文件夹路径；保存或删除本机项目、会话、运行、公开事件和图片附件；读取完成的图文历史 |
| [`chat.py`](../../src/xuanyue/chat.py) | 按会话绑定的内核与模型执行一轮，保存公开事件和终态；首轮成功后另请求会话标题 |
| [`model_config_editor.py`](../../src/xuanyue/model_config_editor.py) | 校验设置页提交的完整模型目录并写入本机配置与私有密钥文件 |
| [`server.py`](../../src/xuanyue/server.py) | 向本机界面提供模型设置、项目、会话、图片附件和运行记录接口 |
| [`desktop/`](../../desktop/) | React 界面、模型选择、轮次导航和公开过程折叠；Mac Electron 窗口提供系统文件夹选择器，不直接读取框架对象或密钥 |

数据库和真实对话放在本机，不纳入 Git。事件按 `(run_id, seq)` 排序；界面重取运行记录时依据已保存内容显示，不把尚未收到的事件假装成完成。服务异常退出后的运行标为中断，原事件保留；用户可以在会话中发起**新一轮**，目前不能从旧 Agent 节点继续原运行。

## 这段尚未覆盖

- 未实现账号登录、多人隔离、经营数据文件导入与分析。当前图片只是模型对话附件，数据库保留用户、项目、会话关系，但当前只有本机用户。
- 工作文件夹只登记路径；Agent 文件读取、目录扫描、文件导入和工作区权限尚未实现。Mac 原生选择器已在开发窗口验收，Windows/Linux 行为未验证。
- 未实现原生内核检查点、旧节点回溯、派生分支、运行中取消或退出后续跑。[目标交互](../architecture/04-workflow-and-trace.md#3-点击旧节点后可以做什么)仍须单独实验和评审。
- 当前工具只有原来的纯计算样例；没有 MCP、沙盒或用户可设置的工具权限。公开事件的范围取决于框架适配器实际给出的内容。
- 模型设置当前只有 OpenAI Chat Completions 兼容协议。界面不探测供应商接口是否连通、模型是否真的接受图片；已有会话的模型 ID 不能在设置页删除，但修改该 ID 的地址或上游名称会影响后续提问。Windows 私有文件权限尚未验收。
- Electron 只作 Mac 上的开发窗口；Windows、Linux 安装、签名、后台进程管理和资源占用未验收。

## 本机验收记录

2026-10-03 在 Mac 开发环境验证公开调用关联：90 项 Python 测试、6 项前端轨迹整理测试、Ruff 检查与格式检查、TypeScript 检查和 Vite 构建均通过。两种主内核各自运行同一组合成双工具任务，事件写入隔离 SQLite 后，界面都显示“2 次模型调用 · 2 次工具调用”。完成运行默认收起；展开第一模型调用可见两个独立工具，进一步展开分别看到输入 `2×3`、`4×5` 和返回 `6`、`20`；滚动后最终答复仍可见。旧事件缺 ID、错父级、重复 ID、未结束和覆盖缺口由纯函数测试核对，不根据相邻顺序补造关系。隔离服务、数据库和浏览器页已关闭并清理；本次未调用真实供应商，也未改现有会话。

复核命令：

```bash
.venv/bin/python -m unittest discover -s tests -v
uvx ruff check src tests
uvx ruff format --check src tests
node --test desktop/tests/activitySummary.test.mjs
npm --prefix desktop run build
```

2026-09-27 的多图输入切片当时有 87 项 Python 测试通过，并做了以下隔离验收：

- 在输入框同时粘贴合成图片和文字，再用文件选择器一次添加三张图片。界面显示四张待发图片；第五张粘贴被拒绝并提示上限。逐张移除后重新添加，发送完成后问答显示四张缩略图。
- 本机假模型收到的图片顺序与界面一致；下一轮文字追问时，四张图片仍按同一顺序作为历史发送。两种主内核经真实框架适配器到本机假供应商的多图顺序也有自动测试。真实视觉模型没有参与这次验收。
- 存储测试覆盖四图顺序在重启后保留，旧单图附件表迁移后仍能回放。HTTP 测试覆盖第五张、重复附件 ID 和跨项目图片被拒绝。隔离项目、服务和合成图片已清理，原有项目与会话未改动。
- 更新本机 8787 服务前，已把现有 SQLite 运行库备份到被 Git 忽略的 `runtime/backups/`；新服务启动后的六张业务表记录数与备份一致，`PRAGMA integrity_check` 返回 `ok`。这只证明迁移没有丢失这些记录，不证明旧会话今后的模型调用质量。

上一段模型设置的隔离验收保留如下：

- 用单独的临时配置和数据库启动本机服务，在页面从空目录新增两个模型和一个供应商；关掉设置页再打开，密钥只显示“已配置”，输入框为空。服务重启后，目录和新会话仍在。
- 在新会话的模型菜单搜索 `model-2` 并按 Enter 选中；内核菜单用方向键选中 LangGraph，Escape 可关闭并把焦点还给选择按钮。创建后会话记录显示 `langgraph · model-2`。
- HTTP 与配置测试验证响应不回显密钥、新密钥保存到权限为 `0600` 的本机文件、旧 `.env` 不变、配置更新立即生效、仍被会话引用的模型不能删除。隔离测试没有调用真实模型，也没有修改现有项目或密钥。

上一段目录创建与运行过程的实际检查保留如下：

- Mac Electron 点击“新建项目”直接打开目录选择器，选定临时目录后以 basename 创建项目；从点击到系统选择器可见三次约为 1.79、1.14、1.11 秒。测试项目和目录已清理，原有项目保留。
- 隔离的浏览器预览用临时库创建项目与无标题会话，发送一条合成算术提问。真实模型答复完成后，侧栏和顶部从“新会话”更新为模型标题；Run 显示 3 秒、两次模型调用和一次工具调用。临时库与目录已清理。
- 对已有两轮会话做只读界面检查：运行完成的过程默认收起；展开第二轮可见模型调用、`multiply` 的输入与返回；右侧两个刻度可点击跳转。620px 与 320px 窄屏下未遮住内容。没有修改已有会话。
- 自动测试覆盖两种主内核首轮自动标题、标题失败后主 Run 仍完成、手动改名优先、旧库迁移及重启时的标题状态收束。

上一段删除功能的实际验收仍保留如下：

- 浏览器预览用合成临时目录创建项目和会话，真实模型完成短文字回合；确认删除会话和项目后，六张相关表均为空。两种主内核还分别在独立临时库完成两轮真实模型测试。
- Mac Electron 开发窗口实际打开系统文件夹选择器，回填规范的绝对路径；创建及确认删除合成项目后，六张相关表均为空。
