## 现在有哪些问题

现有预览已经让 LangGraph 和 AgentScope 分别运行主 Agent，用户选择的内核不会被自动替换；项目、会话、附件和公开事件也由产品保存。这些方向保留。

| 类别 | 现有行为或缺口 | 对用户的影响 | 性质 |
| --- | --- | --- | --- |
| 长会话历史 | 审查基线中，AgentScope 在合成八轮长历史中把全部八个历史标记从实际模型请求中移除，运行仍记为完成 | 用户以为 Agent 看过完整历史，回答可能漏掉前文 | P1，A1 已针对产品模型入口修复待审；真实供应商未验 |
| 工具异常 | 审查基线中，AgentScope 把合成工具异常正文交给下一次模型请求，并写入公开事件和本机数据库 | 异常中若含敏感内容，可能继续外传或显示 | P1，A2 已在两种内核共用的工具边界修复待审；未发现真实密钥泄露 |
| 模型调用轨迹 | LangGraph 达到循环上限时，实际发起四次模型请求，却记录五次“模型调用开始” | 轨迹和调用次数不可信 | P2，已复现偏差 |
| 运行绑定与出站授权 | 旧 Run 未保存当时的非密钥模型目的地与版本；同一模型 ID 改地址后，后续提问会把历史发往新地址，当前没有逐次出站授权 | 用户无法复原旧运行用了哪个服务，也无法按目的地控制历史与图片的发送 | 真实数据接入前的门槛；合成配置验证，未发生真实外发 |
| 统一限制与附加调用 | 两套框架的循环上限含义不同，没有产品级总时长、调用/工具预算；自动标题请求未单独记录用量 | 难以比较两种内核的终止原因或掌握总消耗 | 扩展长任务前的门槛；尚未交付的 K1 能力 |

审查基线的 90 项 Python 测试、6 项前端测试、构建和 Ruff 检查通过，说明原有测试覆盖的行为可运行；额外合成场景复现了前三个偏差。合成结果不能推断真实供应商的回答质量、费用或已经发生的数据外发。

## 一次只修一段

下面 A1、A2 已实现；A3–B3 仍是**建议顺序**，不是已批准的排期。每段完成后提交可审阅的代码、两种内核的合成结果、失败样例和时间线更新，再讨论下一段。后三段在真实经营数据和新数据工具接入前完成；取消、恢复、双向委派、工作流和经营数据分析继续按原计划单独评审。

| 切片 | 要改的行为 | 本段验收证据 | 待评审的选择 |
| --- | --- | --- | --- |
| A1：历史完整性，已实现待审 | 未获批准的框架压缩、摘要或截断不能悄悄改变模型输入；供应商拒绝时停止，不保存为正常完成 | 短历史、八轮长文字与六张跨轮图片检查两内核**实际交给 ModelClient 的有序输入**；本机假供应商拒绝完整长请求后，Run 保存为 failed，无完整答案和完成事件 | 当前没有可信的模型容量登记与图像 token 估算；容量未知时发送完整输入，由供应商拒绝过长请求。真实供应商行为与费用未验 |
| A2：工具异常安全，已实现待审 | 产品工具执行边界把异常变成固定失败结果；模型工具参数在 SDK 调度前严格校验 | 两种真实内核的后续模型输入、公开事件、SQLite 记录和界面均不含合成异常正文；失败工具保留 error 状态 | 当前只公开固定错误文案；执行失败后允许模型解释，非法模型参数则终止整轮。扩展业务错误另行评审 |
| A3：模型调用事件真实 | 只有模型桥实际开始一次调用，才写“模型调用开始”；未调用时不能预报下一次 | 正常回合、并行工具、循环上限、调用前校验失败和调用中异常；以 ModelClient 的实际调用次数和终态对照公开事件 | 是否另设“待调度”事件；它不能计入模型调用次数 |
| B1：Run 模型快照 | 新 Run 保存不含密钥的目的地、上游模型、配置版本和内核/适配器版本；旧 Run 的缺失值显示未知 | 改动模型目录前后创建 Run，旧记录仍可查到原绑定；不能从现行配置反填旧记录 | 快照字段、版本标识与旧库迁移方式 |
| B2：模型出站授权 | 每次模型调用核对当前项目、目的地和本次发送范围，包含历史、图片和标题请求；目的地或范围变化要重新匹配授权 | 合成目的地切换和范围变化被拦截或重新授权；拒绝后不发请求；两内核一致 | 授权范围与 UI 提示方式，须由用户评审 |
| B3：产品级执行限制 | 统一计算单 Run 的模型调用数、工具执行数和整体截止时间；框架自己的迭代上限只作第二道限制；标题调用独立记账 | 两内核在相同产品限额下给出可比的超限原因；标题请求的状态与用量可查，供应商未返回用量时标未知 | 首版限额值、标题是否占会话总预算和并发限制范围 |

A2 和 A3 分别处理数据安全与轨迹真实性，不并成一次重写。B1 先让旧、新运行的目的地可识别，B2 再决定和实现出站授权；快照不能代替每次调用时的有效授权。B3 不把两个框架自己的 `max_iters` 与 `recursion_limit` 当成同一单位。

### A1 的实际结果（2026-10-05）

[AgentScope 适配器](../../src/xuanyue/engines/agentscope.py)通过 SDK 的上下文压缩 middleware 跳过自动摘要及截断，并关闭压缩失败后的截断回退；模型桥还会核对转换后的任务历史与本轮输入仍完整、有序地位于 system 消息之后。若将来 SDK 改写历史，适配器会在调用产品 `ModelClient` 前报错。没有给模型容量编造一个统一数值，也没有把 SDK 默认的 32,768 token 当作所选模型的真实上限。

[回归测试](../../tests/test_conversation.py)先在原实现上复现历史丢失，修复后核对两种内核的八轮长文字和六张跨轮图片全部进入产品模型请求；AgentScope 在工具返回后的第二次模型请求也保留长历史与图片。2026-10-06 复核补上了[HTTP 与持久化测试](../../tests/test_chat_service.py)：两内核将完整长历史发给本机假供应商；返回 HTTP 400 后，Run 保存为 failed，完整答案为空，也没有完成事件。隔离浏览器中，两内核对应会话均显示“运行失败”。95 项 Python 测试、6 项前端测试、Ruff、格式检查、TypeScript 检查和构建通过。尚未用真实供应商验证容量拒绝、费用和视觉理解；产品模型接口之后的供应商内部处理也不在本次观察范围。当前没有调用前的容量检查；模型桥的历史校验也不覆盖 system 提示词和本轮新生成的工具结果。工具结果过长时 SDK 另有截断逻辑，不在 A1 的用户历史验收范围，需在工具结果切片评估。

### A2 的实际结果（2026-10-07）

例如，读取工具抛出一个含内部信息的异常，用户应看到“工具执行失败，请稍后重试。”，模型也只收到这句固定说明。模型随后可以解释未取得结果，但轨迹中的工具仍显示失败；整轮答复完成不代表工具成功。

实现放在现有职责内，没有新建一套工具框架：

- [类型定义](../../src/xuanyue/types.py)增加 `ToolExecution` 和六个固定错误码：参数不符、未获授权、工具不可用、资源不存在、返回格式错误、未知执行失败。
- [产品工具边界](../../src/xuanyue/tools.py)提供 `execute_tool`。未知异常、异常链和非文字返回对象不会被转成公开正文；已分类业务错误只能选择固定码，不能附带任意“安全文本”。每次调用仍由 `ToolService` 校验和授权。
- 两种内核各自把结果转换成原生失败状态，并保留调用 ID。AgentScope 使用 `ERROR` 工具结果；LangGraph 只用产品固定文案构造 `ToolException`，再转为原生 `status=error`。
- 模型桥先调用共同的 `parse_tool_arguments`，拒绝非法 JSON、非对象、非有限数和 schema 不匹配。AgentScope 2.0.8 默认会修复参数，前置校验避免字符串数字被悄悄转换。**同一模型回复中，只要一个调用参数非法，整组都不进入 SDK 调度，整轮保存为失败。** 已合法派发、但执行失败的调用则返回安全结果，允许模型继续解释或经重新授权后重试。

依据是本机安装的 AgentScope 2.0.8（`tool/_toolkit.py` 的调用与异常处理、`_utils/_common.py` 的 JSON 修复）以及 langchain-core 1.6.5（`tools/base.py` 的 `ToolException` 转换），查阅日期 2026-10-07。测试使用 LangGraph 1.2.12、LangChain 1.4.0；锁定版本与前后对照见[合成复核记录](../../research/spikes/design-alignment-audit/a2-recheck-20261007.json)。

[专项回归](../../tests/test_tool_errors.py)检查实际到达 `ModelClient` 的请求、公开事件和 SQLite 全部逻辑记录，覆盖权限拒绝、业务错误及异常链、未知异常、非文字返回、并发成功与失败、非法参数和取消传播。成功返回中包含 `error` 一词不会被误判为失败。两种内核在隔离浏览器中都显示“执行失败”和固定文案；[界面记录](assets/tool-error-agentscope-20261007.png)使用合成数据，测试配置没有可用密钥，输入框因此禁用。

全量 Python 回归、Ruff 与格式检查的本轮结果见[时间线](progress.html)。原审查脚本使用相同输入复核：两内核都不再将异常标记写入公开事件或后续模型请求，八轮历史仍完整到达。LangGraph 循环上限仍是 **4 次真实请求、5 次开始事件**，留在 A3 修复。本轮没有更改前端代码，使用上一切片的构建产物做界面验收。

范围限制：未调用真实供应商，不证明模型会正确解释或重试；不扫描成功工具正文中的敏感内容，不评估工具长结果截断。只验证公共工具包装不会吞掉 `CancelledError` 或其他 `BaseException`，不表示产品已支持取消。B1–B3 的目的地、授权与限额缺口仍在。

## 每段怎样结束

修复前保留审查报告里的失败输入；修复后用同一输入复核两套真实框架适配器，并加入必要的自动回归。记录实际模型请求、公开事件、数据库终态和界面所见，不能只检查任务入口参数。运行中断、能力未知或供应商用量缺失时，写清未验证范围。只有这一段的验收证据齐全，才把时间线节点改成已完成；后面的候选仍留待讨论。
